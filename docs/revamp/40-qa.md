# Phase 4: QA and release (plus Q0, the measurement harness)

Lighthouse, device runs and the visual sweep are recorded in PRs and here. They are not CI gates (`AGENTS.md`, merge gates), but the revamp is not released until Q1–Q5 pass.

---

## Q0: Measurement harness in the repo

- **When:** Phase 1, in parallel with U1 and B1–B6. It owns only new paths, so nothing conflicts.
- **Why:** perf budgets and visual checks need the same scripts and data as the 2026-11-23 baseline. Today those scripts live outside the repo.
- **Owned paths:** `scripts/perf/**` (new), `scripts/visual/**` (new), the move of `reference/android-kit/` into `scripts/perf/android/`, the "Reproduce" section of [`reference/perf-baseline.md`](reference/perf-baseline.md), and its own root `package.json` script entries (shared config rule).
- **Scope:** port the audit scripts:
  - The Lighthouse runner with fresh sign-in.
  - The signed-in throttled flow with CPU profiles and source-map attribution.
  - The API benchmark and synthetic data seeder: 170 and 500 clients, in a separate database, never the remote one.
  - The web screenshot sweep at 1440 and 390, light and dark.
  - The iOS capture script.

  The Android kit (`reference/android-kit/`) moves to `scripts/perf/android/`.

- **Rules:**
  - Scripts read the database URL from an explicit argument or variable and refuse a non-local host.
  - No credentials in files. Test credentials come from the seed (`AGENTS.md`, secrets).
  - `set -euo pipefail`; a non-zero exit on failure.
- **Done when:**
  - Each script runs from a clean checkout, following the README instructions in `scripts/perf/`.
  - Each scenario runs 5 times on `main`; `perf-baseline.md` gains the median and min–max per scenario. That spread is what later budget checks compare against (medians, same data and settings).

## Q1: Visual and states sweep

- Every route, on web at 1440 and 390, iOS and Android; light and dark; the states each spec lists.
- Compared against the approved mocks. Every difference is listed in `status.md` and is either fixed or accepted by the owner there.
- **Pass:** zero unlisted differences; the client header on every client route; zero task screens with a tab bar; zero screens with content under system UI; every state each spec lists exists on every platform.

## Q2: Performance against the budgets

- Run the Q0 harness on the release candidate and fill in the "After" column of [`reference/perf-baseline.md`](reference/perf-baseline.md).
- Every budget in [README §9](README.md#9-performance-budgets-from-the-baseline) is met. A miss is fixed, or the owner accepts it in [`rulings.md`](rulings.md) with its number.

## Q3: Accessibility and RTL

- Automated: axe on every web route, with no serious or critical issues. Zero React unknown-prop warnings.
- Manual:
  - VoiceOver on iOS for Today, check-in, the plan editor and intake.
  - TalkBack on Android for the same four.
  - Keyboard-only on web for the same four, including `⌘K`.
- Dynamic Type at the largest accessibility size on Today, check-in and the plan editor: no clipped or mid-word-broken labels.
- Reduced motion and Reduce Transparency on all three platforms.
- An RTL smoke: force `dir="rtl"` on web and RTL on native. Layouts mirror, directional icons flip, numbers with units stay readable. There are no Urdu strings yet (non-goal).

## Q4: Devices

- **iOS:** a ProMotion iPhone for 120 Hz, plus the simulator matrix.
- **Android:** the owner's low-end device (rulings O2), release build. It is run on the owner's other MacBook with the kit:
  - Cold start median 1.5 s or less.
  - Roster scroll jank 5% or less.
  - Every focal animation (verdict reveal, publish stamp, chart draw-in) has 5% or fewer janky frames (Perf Monitor or HWUI bars, release build).
  - **Pass:** all of the above on the chosen device, recorded with the device name, build type and scenario.
  - Glass on API 31+ and the solid fallback below API 31.
- **Release gate (R2):** Android glass ships only if this pass is clean. Otherwise it ships with Solid bars as the Android default until fixed.
