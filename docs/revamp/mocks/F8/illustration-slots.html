Theme

1. Empty-state slots in context

Six slots, each a Lucide kit icon on a tinted disc. They sit inside a bg.surface panel next to the screen's title, one line of copy and its action. Copy follows the screen specs (S02, S03, S06, S12); lines a spec does not give are proposals.

2. Export contract

One component per slot in packages/ui/src/illustrations/. L1 swaps the art behind these names and props, so no screen changes. A test fixes each name and its props.

Today's art next to the Floodlight login form, at the sizes S01's layout uses: on web at 768 px and wider the hero and form columns split the window 50/50 until the form reaches its 560 px cap at 1120 px, then the hero takes the rest (auth-split-layout.tsx, auth-form-column.tsx), cropped to cover; below 768 px web hides it. Proposed sizes: max(50vw, calc(100vw - 560px), 75vh): the column is half the window below 1120 px and the window minus the 560 px form above it, and cover on a tall window is set by height (the art is 3:4). Finding: at 2× on tablets and laptops the column wants more than 864 px (for example 1268 px at 1194 × 834), so those screens get the 864 file slightly upscaled, as today. The saving comes from the format, not from sharper art. L1's redraw can export larger.

4. Tablet (rulings O8)

At 834 (iPad 11-inch portrait) and 1194 (landscape) the app uses the tablet layout under F1's proposed edges (744 to 1199). F6 designs the tablet shell, so navigation is a dashed placeholder here. Slots stay centred in the content column at the regular size; the hero keeps today's split rule.

5. For the owner to approve

  1. Component names: IllustrationNoClients, IllustrationNoMatches, IllustrationNoPlan, IllustrationInboxClear, IllustrationNotFound, IllustrationError, plus AuthHero.
  2. Props: size?: 'regular' | 'compact' and testID? for each slot; variant: 'column' | 'band' and testID? for AuthHero. A test fixes them.
  3. Icons: UserPlus, SearchX, ClipboardList, Inbox, Compass, CircleAlert.
  4. Tints: Sunflower wash for first run and no plan; neutral bg.sunken for no matches and 404; bg.sunken with the icon in status.success.text for Inbox clear, a calm state with no status fill (ruling T6); danger wash for the generic error, which needs action. Each disc has a 1px border.subtle ring.
  5. Disc edges: in light the disc fills are about 1.1:1 against the surface, and in dark the bg.sunken discs equal the canvas (1.00:1), so only the 1px ring separates them. The slots are decorative, so WCAG 1.4.11's 3:1 does not apply. Options: keep the faint disc plus ring, or use a stronger tint. Recommended: keep it, because the title carries the meaning and a stronger tint would compete with the action.
  6. All six slots are decorative (empty alt), since the title beside each says the same thing.
  7. The auth hero becomes decorative too (empty alt). Today it has the label "Illustrated mat, dumbbells, bottle, and progress phone".
  8. Tablet login: keep today's 50/50 split (a 417 × 1194 hero column at 834 portrait), or use the header band below 1024 px. Recommended: the band, because a tall 417 px column crops the art to its middle third while a band keeps it legible above the form. S01 decides the layout; F8 only supplies the column and band variants.
  9. Hero files at 648 and 864 wide, in AVIF and WebP, with sizes="max(50vw, calc(100vw - 560px), 75vh)". No 432 file, since no window at 768 px or wider would use it.
  10. Native hero file: PNG as F8 requirement 3 says (about 1.5 MB at 864, estimate), JPEG (about 306 KB, estimate) or WebP (about 120 KB, estimate). Recommended: WebP, which both platforms decode, because a PNG of this painted, photo-like art is about 13 times heavier. Picking WebP or JPEG changes F8 requirement 3; the coordinator updates the spec only after the owner decides.
  11. Today's "All clear" (S02) stays text only, as its spec says.
