F3 glass sheet

Glass chrome for the GymOS revamp (ADR-0019 decision 6, rulings R2). Glass covers only the top bar, tab bar, sticky client header and sheets, on iOS, web and Android. Everything is synthetic demo data.

Provisional. Colours come from F1's proposed token set (F1 token sheet, PR #140, not yet approved by the owner). This sheet changes if F1 changes.

1. The four chrome surfaces over busy content

Web reference, tokens exact. The client list and weight chart scroll under the chrome. Chrome glass carries fg.primary text and icons only. Sheet glass may carry secondary text, a link and an input.

2. Per platform

Same screen on each platform. The iOS and Android looks are browser approximations: real screenshots come from the iOS simulator and the owner's Android kit. All use the same tint tokens, so the legibility numbers hold.

Web at tablet and desktop width

From 744 px wide the sheet uses its 32 px blur token; below that it is capped at 20 px. Each frame keeps to two glass layers or fewer. Tablet and desktop shells are F6's mock; this sheet covers chrome glass only.

3. Each fallback

Every trigger switches the chrome to the solid glass.fallback (light bg.surface, dark bg.raised). High contrast also draws border.control edges. The last two frames show the sticky header and the sheet in the fallback.

4. Budget rules

The numbered markers point at each rule. The checks under the list run in this page.

  1. At most two glass layers per viewport. Here the sticky header and the sheet. The tab bar sits under the scrim and turns solid, because it would be a third layer.
  2. Blur at most 20 px on phones. Chrome uses glass.blur.chrome (20 px). The sheet token is 32 px, so below 744 px wide it is capped at 20 px; from 744 px up the sheet uses 32 px (section 2).
  3. Never on a scrolling list. The list rows and cards are solid bg.surface; only the chrome over them is glass.
  4. Chips inside glass sit on an opaque pill. The severe-allergy chip is solid status.danger.solid with an icon and words, never glass, never tenant-coloured.
  5. Focus on glass gets a 2 px surface halo. The focused "More" button shows the focus ring with a 2 px bg.surface halo inside it.

5. Legibility numbers

Computed in this page: each text token over the tint at its token alpha, laid over each of 46 solid backdrops (black, white, and steps 300, 500, 700 and 900 of every colour family, per tokens.md §9.3). A blurred backdrop is an average of what is behind it, so the solid patches bound it. Chrome needs 7:1 for fg.primary; sheet text needs 4.5:1. Ratios show two decimals; pass or fail uses the unrounded value. Dark fg.secondary passes on the sheet with almost no headroom.

Rule: fg.faint and placeholder text never sit directly on sheet glass. Placeholders sit inside the opaque bg.field of an input, as in the Log weight sheet's Note field.

6. Where glass is never used

A table, a form and a data card stay solid, next to glass chrome. Anything the coach reads closely, compares or types into is solid.
